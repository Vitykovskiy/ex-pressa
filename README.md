# ex-pressa

Телеграм-бот на NestJS. База данных — PostgreSQL

## Требования

- Node.js 20+
- Docker

## Установка

```bash
npm install
```

## Настройка окружения

Используется файл окружения `.env`

## Запуск (dev)

База PostgreSQL в Docker, приложение локально:

```bash
docker compose -f docker-compose.dev.yaml up -d
npm run start:dev
```

## Тестовая база данных

Для ручного и автоматизированного тестирования используется отдельная PostgreSQL
на порту **5433** с автоматическим наполнением при старте приложения.

### Запуск

```bash
# 1. Поднять тестовую БД (данные не сохраняются между перезапусками)
docker compose -f docker-compose.test.yml up -d

# 2. Запустить приложение — TypeORM создаст схему, затем автоматически засидирует данные
npm run start:dev
```

Приложение обнаруживает файл `.env.test` и подключается к тестовой БД вместо dev-БД.
Все остальные переменные (`TELEGRAM_BOT_TOKEN`, `AUTH_JWT_SECRET` и т.д.) берутся
из `.env` как обычно.

### Сброс данных к дефолтному состоянию

```bash
docker compose -f docker-compose.test.yml down   # удаляет контейнер и данные
docker compose -f docker-compose.test.yml up -d  # поднимает чистую БД
# перезапустить приложение — seed сработает снова
```

### Дефолтный набор данных

| Что | Данные |
|-----|--------|
| Роли | USER, BARISTA, ADMIN |
| Пользователи | Тестовый пользователь (USER), Анна Бариста (BARISTA), Владелец кофейни (ADMIN), Иван Тестовый (USER, неактивен) |
| Каталог | Напитки: Капучино и Латте (размеры S/M/L), Еда: Круассан; Сиропы: Ваниль и Карамель |
| Тайм-слоты | Сегодня + 6 дней вперёд, 3 слота/день (09:00–09:30), вместимость 5 |
| Заказы | #1 CREATED, #2 CONFIRMED, #3 READY, #4 REJECTED |

### Как работает автосидирование

`SeedService` запускается в `onModuleInit` при `SEED_ON_START=true`.
Если в таблице `roles` уже есть записи — сидирование пропускается (идемпотентно).
На dev-БД сидирование не запускается (`SEED_ON_START` отсутствует в `.env`).

### Переменная окружения

- `SEED_ON_START` — `true` запускает сидирование при старте приложения (задаётся в `.env.test`)

## Swagger

После запуска приложения Swagger доступен по адресу:

- `http://localhost:<PORT>/docs` (`PORT` в `.env`)

## Запуск (prod)

1. Создать `.env` на сервере
2. Установить зависимости и собрать проект:

```bash
npm install
npm run build
```

3. Запуск:

```bash
docker compose -f docker-compose.prod.yaml up -d
```

## Переменные окружения

- `TELEGRAM_BOT_TOKEN` — токен бота
- `AUTH_JWT_SECRET` - ключ для верификации JWT
- `DB_HOST` — хост PostgreSQL (dev: `localhost`, prod: `postgres`)
- `DB_PORT` — порт PostgreSQL (обычно `5432`)
- `DB_USER` — пользователь БД
- `DB_PASS` — пароль БД
- `DB_NAME` — имя БД
- `PORT` — порт приложения
- `WEB_APP_URL` — URL веб-приложения
- `SKIP_AUTH` — `true` отключает проверку JWT (только для разработки, устанавливает мок-пользователя со всеми ролями)
- `SEED_ON_START` — `true` заполняет БД тестовыми данными при старте приложения
